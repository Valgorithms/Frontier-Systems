# Constructed room topology foundation

`ConstructedRoomTopology.assess` is a pure, bounded descriptor assessment. Production remains the canonical wall owner. The helper owns no world state, cache, room IDs, pressure records or persistence; it runs only when explicitly called, never per tick. Its v1 result is documented in `docs/schema/constructed-room-topology-v1.schema.json`. `production_revision` identifies the supplied snapshot, not a freshness or authorization guarantee. Callers remain responsible for obtaining canonical descriptors and rechecking revisions before any future integration.

## Supported geometry

Input has the exact `constructed-wall-boundaries-v1` shape: schema/revision/boundaries, at most 32 unique panel IDs, finite integral coordinates within +/-100500 mm, height 2000 mm and thickness 100 mm. JSON integer-valued floats are accepted and normalized to integer output. Extra fields, booleans, fractions, invalid numbers, zero-length or diagonal spans, nonzero base heights, duplicate IDs and positive-area overlapping wall solids fail with `invalid_room_topology`. Bounds and count checks happen before geometry traversal. No partial result escapes a validation failure.

The supported subset is exactly one rectangular wall band at ground level, with positive interior width/depth. Two parallel sides act as full-width caps; the perpendicular pair fit exactly between their inner faces. Either X or Z may be the cap direction. Collinear panels may partition a side into contiguous non-overlapping intervals. Endpoint direction and insertion order do not matter. Coverage uses exact integer millimetres without tolerance or snapping. Every solid must belong to exactly one of those four sides and cover its required interval, with exact face contact at corners. Mixed corner styles, centreline intersections, T joins, interior partitions, nonrectangular arrangements, extra/disconnected branches, multiple rooms and gaps are outside this subset. Intersecting solids are invalid; other valid but incomplete or unsupported arrangements return `open_or_unsupported` with empty bounds. This deliberately does not distinguish every open shape from every unsupported closed shape.

`closed_wall_perimeter` means only that the supplied ideal panel solids cover this wall band. `interior_bounds_millimetres` is `[min_x, max_x, min_z, max_z]` at the inner faces. The helper always reports `required_surfaces: [floor, ceiling]`. It accepts no floor or ceiling evidence and never claims a complete room, gas volume, physical seam quality, sealing, pressure, material health or gameplay functionality. Surface thickness/materials, doors, penetrations, damaged walls and connectivity to pressure volumes need separate authoritative contracts.

## Current construction limit

PR128's adapter describes existing 1000 mm panels, 100 mm thick, placed on a 100 mm position grid with overlaps prohibited. Exact perpendicular butt contact needs a 50 mm relative offset that this grid cannot express. Canonical adapter fixtures therefore remain open/unsupported; the synthetic closed fixtures demonstrate mathematics only and are not playable construction evidence. Descriptor schema v1 permits variable spans and integer positions, so the helper can assess such detached inputs without asserting current production can create them. It does not loosen canonical placement validation.

A successor must explicitly decide whether to support a 50 mm placement grid or a dedicated corner/join component, then update canonical placement/collision validation, material ownership and persistence contracts together and test complete surface construction. Merely marking nearby centreline endpoints connected would create an unsupported enclosure claim. This change does not implement that successor.

## Verification and ownership

Only the new helper/UID, test/UID, result schema and this document are owned by this task. Production, pressure, reservations, CI, presentation, shared schemas and captures are untouched. Worst-case work is bounded by 32 panels: O(n squared) overlap checks plus four small interval sorts for each orientation; no unbounded traversal or external effects. No diagnostics are added to simulation ticks; existing runner logs record focused contract failures.

Focused tests exercise mathematical closure, both orientations, segmented coverage, order/endpoint reversal, input/output detachment, JSON numbers, missing sides, 1 mm gaps, interior/exterior branches, malformed/extra fields, duplicate IDs/solids, intersections, numeric and capacity controls, and current canonical adapter output. Use the versioned runner with `-TestNames constructed_room_topology_test.gd,constructed_wall_boundaries_test.gd` and Godot 4.7.2. Verification results will be recorded after the Coordinator runtime lease. No graphical capture is needed for this pure mathematical contract; playable construction, pressure, floor/ceiling integration and deployment remain unverified.

Windows local verification completed with Godot `4.7.2.stable.official.ed1daf0bf` using the existing bounded runner: import, startup, `constructed_room_topology_test.gd` and `constructed_wall_boundaries_test.gd` all passed (4 checks, 0 failures), logs/JUnit in ignored `var/ci/topology-focused-final/`. The first run found an incorrect negative-test expectation for an empty descriptor array; that fixture was corrected to an object and the four checks were rerun successfully. The result schema parsed as JSON; independent JSON Schema validation was not run because the bundled Python lacks `jsonschema`. Windows/Linux required CI remains the remote acceptance gate for the final pushed head. No configuration variables or production dependencies changed.
